# DInFilt

用于某一轴上所有数字量输入的软件消抖滤波器。

## 概述

`DInFilt` 设置一个消抖滤波器：原始数字量输入必须连续 `DInFilt` 个采样保持相同的新值，该变化才会被确认；如果在该区间内的任意时刻输入回落到原来的电平，计数就重新开始，因此短于滤波窗口的毛刺永远不会传播。例如，`DInFilt = 3` 要求连续三次读到 “1”，“1” 才会被确认。它是[数字量输入信号路径](00-overview.md)的第一个环节，并在硬件中运行：输入的采样速度远快于控制环（每次采样约几十纳秒），消抖结果每个控制周期反映到 [DInPort](DInPort-DInPortHigh.md) 一次。

`DInFilt` 是一个单一的每轴值（例如 `CDInFilt` 设置 C 轴／模块的滤波器）。消抖以延迟被接受边沿（延迟量为滤波长度）为代价提高抗噪能力。关于当前固件实际对哪条输入路径进行滤波，参见[工作原理](#how-it-works)。

## 工作原理

写入 `DInFilt` 会将该值下推到硬件：4 位设置（`0`–`15` 范围）被写入硬件滤波寄存器。该寄存器将每轴一个 4 位滤波设置（A、B、C）打包进单个字中，因此每个轴各自携带自己的消抖长度。消抖在硬件中完成，而非在控制环软件中完成；值为 `0` 时禁用消抖（原始读数直接通过）。

在当前固件中，`DInFilt` 接线到**脉冲/方向捕获**输入路径（计入 [DInPort](DInPort-DInPortHigh.md) 相关位置捕获的步进/方向信号），在该路径上，触点抖动或线路噪声否则会被误计为额外步数。硬件还为通用隔离/集电极开路与差分数字量输入（原点、限位等）包含一个独立的、更宽的每端口消抖滤波器，但当前固件将该滤波器保持在其最小（实际上不滤波）设置。因此，提高 `DInFilt` 可可靠地净化脉冲/方向捕获路径；请勿假定仅凭它本身就能为接到通用数字量输入上的开关消抖。

### 硬件行为

消抖器在固定的硬件节拍上对输入采样（脉冲/方向路径约 80 ns）。每个节拍，它将新采样的电平与当前正在呈现的电平进行比较；当二者不同时，它对节拍进行计数，只有当计数达到 `DInFilt` 阈值时，才接受新电平并复位计数器。在该窗口内任何回到先前已接受电平的情况都会立即将计数器复位为零。因此，接受延迟约为 `DInFilt + 1` 个节拍（阈值加上输入同步节拍），而短于该窗口的扰动会被直接拒绝而非取平均。

对于脉冲/方向路径（约 80 ns 节拍），由此得到的最小接受延迟约为：

| `DInFilt` | 近似接受延迟 |
|-----------|--------------------------|
| 0         | pass-through (no debounce) |
| 3         | ≈ 320 ns |
| 8         | ≈ 720 ns |
| 15 (max)  | ≈ 1.28 µs |

这些数值假定为标准的脉冲/方向采样节拍；确切值因产品而异。

## 示例

```text
ADInFilt=3           ; require 3 consecutive matching samples
ADInFilt              ; read back the filter setting
```

### 边界情况

- **超出范围** —— 有效范围为 `0`–`15`；超出该范围的写入会以超出范围错误被拒绝，存储值保持不变。
- **零值** —— 禁用消抖；直接使用原始硬件读数。
- **每轴作用域** —— 每轴/模块一个滤波长度；无法在同一轴上独立于其他输入对单个输入消抖。在当前固件中，该设置作用于脉冲/方向捕获路径（见[工作原理](#how-it-works)）。
- **边沿检测延迟** —— 消抖会将上升沿和下降沿都延迟至多 `DInFilt` 个原始采样周期；对于时间关键的输入（例如高速率的启动运动触发），请优先选用仍能拒绝噪声的最低滤波值。
- **电机使能／失能** —— 无论 `MotorOn` 状态如何，都在硬件中运行。
- **保存** —— 可保存至闪存；启动时重新载入硬件寄存器。
