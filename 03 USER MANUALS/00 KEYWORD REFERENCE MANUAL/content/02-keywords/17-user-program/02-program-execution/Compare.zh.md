# Compare

低级用户程序操作码，从栈中弹出两个值进行比较，并将 1 或 0 压入栈中。

## 概述

`Compare` 是一个低级用户程序语言关键字。涉及 `Compare` 的语法通常由 PC Suite 在编译期间自动生成，而非手动编写，因此它是程序流程控制中关系运算符的基础，例如 [Jump](Jump.md) 所使用的条件。

`Compare` 从数值栈中弹出一个或两个值并进行比较。若结果为真，则将 `1` 压入栈；若为假，则压入 `0`。索引值选择执行哪种比较（以及操作数数据类型），操作数必须在调用 `Compare` 之前已压入栈中。结果仅放在数值栈上；当 `Compare` 通过通信发出时，控制器仅返回 OK 确认（比较值不通过通信通道返回）。

在本页中，`pop1` 是首先弹出的值（栈顶），`pop2` 是其后弹出的值（其下方的值）。双操作数比较读作 `pop2 (运算符) pop1`：例如，"大于"操作在 `pop2 > pop1` 时为真。由于先压入的操作数位于后压入操作数的下方，这意味着测试读取顺序与源表达式的自然从左到右顺序一致——左操作数先压入，右操作数后压入。

## 工作原理

索引选择比较操作及操作数数据类型。在 v4（单机和 Central-i）上，八种比较操作仅适用于 **32 位整数**操作数——操作索引 `2`–`9`。在 Central-i v5 上，相同的八种比较也为 **32 位浮点数**（`10`–`17`）、**64 位整数**（`18`–`25`）和 **64 位双精度浮点数**（`26`–`33`）提供，因此操作索引范围为 `2` 到 `33`。编号从 2 开始，是为了与相关关键字使用的操作编号保持兼容；在 v4 控制器上使用浮点/长整型/双精度索引将被拒绝为超出范围的操作。

| 操作 | 32 位整数 | 浮点数 | 64 位整数 | 双精度 | 为真的条件 |
| --------- | -------------- | ----- | -------------- | ------ | ------- |
| `==`（等于）         | 2 | 10 | 18 | 26 | pop2 == pop1 |
| `>`（大于）   | 3 | 11 | 19 | 27 | pop2 > pop1  |
| `>=`（大于等于） | 4 | 12 | 20 | 28 | pop2 >= pop1 |
| `<`（小于）      | 5 | 13 | 21 | 29 | pop2 < pop1  |
| `<=`（小于等于）    | 6 | 14 | 22 | 30 | pop2 <= pop1 |
| `!=`（不等于）     | 7 | 15 | 23 | 31 | pop2 != pop1 |
| 为零                 | 8 | 16 | 24 | 32 | pop1 == 0    |
| 非零             | 9 | 17 | 25 | 33 | pop1 != 0    |

"为零"和"非零"操作取单个操作数（`pop1`）；其他操作取两个操作数。操作数必须已在栈上，比较时将其移除。压入的单个 `1` 或 `0` 结果正是条件 [Jump](Jump.md)（操作 8，"若为零则跳转"，或操作 9，"若非零则跳转"）随后消耗的值——因此关系测试后跟条件跳转是编译器构建 `if`、`while` 和 `for` 结构的方式。

## 示例

```text
; Generated by the PC Suite — push two operands, then compare
ACompare[2]          ; pop2 == pop1 ? push 1 : push 0
ACompare[5]          ; pop2 <  pop1 ? push 1 : push 0
ACompare[8]          ; pop1 == 0   ? push 1 : push 0  (single operand)
```
