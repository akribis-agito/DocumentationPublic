# Load

将所有参数从闪存重新加载至易失性存储器，丢弃未保存的更改。

## 概述

`Load` 将所有可保存至闪存的参数从非易失性（闪存）存储器检索到活动的（易失性）参数表中。控制器在上电时会自动执行一次该操作；手动发出 `Load` 会**在不重新上电**的情况下重复该操作。

`Load` 会覆盖易失性存储器中的每一项未保存更改。这使其成为从错误的、未保存的配置中快速恢复的方法：`Load` 将控制器恢复到闪存中存储的上一组已知良好的参数。某个给定参数是否参与，由其 `flash` 属性决定（显示在每个关键字的 Quick Facts 中）。它是一条**命令**（无值），并且**不允许在电机使能或运动中时使用**。

## 工作原理

`Load` 是 [Save](Save.md) 的逆操作，并且能够容忍写入闪存的固件与读取闪存的固件之间的差异：

1. **校验校验和。** 对整个参数区求和，并与 `Save` 存储的累加校验和进行比较。不匹配时，`Load` 报告校验和错误（30），且存储的参数集不会被应用；在上电时，此错误（或任何其他加载错误）会触发恢复为默认值——参见下面的边界情况。
2. **回放记录。** 从参数区的起始位置开始，`Load` 读取每条记录的 CAN code（以及打包的轴编号）、元素计数和值，然后将这些值写回匹配的实时参数——但仅当该关键字在当前固件中仍具有 `flash` 属性时才会写入。它会在 `Save` 写入的最后一个 CAN code 标记处停止，或在到达已擦除（`0xFFFF`）的闪存时更早停止。
3. **协调布局。** 闪存与运行固件之间的逐参数不匹配会被平滑处理，并作为警告而非硬错误记录到[错误日志](../../07-status-and-faults/ErrLog.md)中：
   - **数组变大**——多出的元素以其默认值填充。
   - **数组变小**——多余的已存储元素被跳过。
   - **轴数减少**——对应于不再存在的轴的记录被跳过。
4. **范围检查。** 每个加载的值都会对照其最小/最大限值进行检查；超出范围的值将被替换为该参数的默认值（并记录一条警告）。
5. **重新推导状态。** 加载之后，固件会重新运行每个参数的“特殊”初始化，将环路滤波器标记为已修改，并为每个轴重新计算滤波器，以使派生的内部状态与新加载的值相匹配。

参数校验和（[ParamCS](../01-status/ParamCS.md)）会在加载过程中重新计算，因此它反映的是实际恢复的内容。

在 Central-i 上，该命令会被立即确认——一个提前发出的空回复会告知上位机操作已经开始——并且，由于闪存访问可能阻塞通常用于喂养看门狗的环路，固件会预先喂养后台看门狗约 120 秒。上位机应允许大约这么长的时间来等待最终的 OK/错误回复，然后再将 `Load` 视为挂起。

## 边界情况

- **电机使能 / 运动中。** 被拒绝——解释器返回错误。请先停止轴并禁用电机；如果固件在运行期间以某种方式被要求重新加载，则上电时同样适用此限制。
- **校验和不匹配。** `Load` 报告校验和错误（30），且不加载已存储的参数集。手动发出时，`Load` 返回该错误并保持当前实时值不变。
- **上电默认恢复。** 在上电时，固件首先将每个参数初始化为其默认值，*然后*运行 `Load`。如果该加载返回任何错误——闪存校验和不匹配（30）或意外/损坏的存储数据（32）——则所有可保存至闪存的参数都将恢复为其默认值，而不是应用部分参数集。（重新恢复默认值是由任何非零加载错误触发的，而不仅仅是校验和不匹配。）
- **固件升级（参数布局不同）。** 逐参数不匹配（数组变大/变小、轴数减少）会被平滑处理，并在 [ErrLog](../../07-status-and-faults/ErrLog.md) 中记为警告。在新固件中不再具有 `flash` 属性的参数在加载时会被直接跳过。
- **Central-i 断开连接。** `Load` 恢复主轴自身的参数；它不会将这些参数推送到远程单元。逐端口设置（[CIDeviceType](../05-central-i/CIDeviceType.md)、[CILinkConfig](../05-central-i/CILinkConfig.md)、……）会在下一次 [CIConnect](../05-central-i/CIConnect.md) 时生效。

## 示例

```text
ALoad                ; reload all flash-saved parameters, discarding unsaved edits
```
