# 运动模式 —— PVAJ

PVAJ 运动执行**下载的轨迹表**，而非由控制器自行计算的曲线。上位机将位置/速度/加速度/加加速度（P/V/A/J）各行上传至 [PVAJList](PVAJList.md)；控制器以五次多项式在相邻两行之间插值，该多项式在每个区间的两端同时匹配位置、速度**和**加速度，因此三者在每个接缝处均保持连续。

两种运动模式共用同一个执行器，区别仅在于运动命令的作用范围：

| [MotionMode](../02-motion-configuration/MotionMode.md) | 名称 | `Begin` / `Stop` / `Abort` 作用于 |
|---|---|---|
| `22` | PVAJ | 仅被命令的轴 |
| `23` | MultiAxisPVAJ | 当前处于模式 `23` 的所有轴，作为一个协调运动组 |

## 操作顺序

上传 → [PVAJValidate](PVAJValidate.md) → [PVAJArm](PVAJArm.md) → `Begin`。

使能（Arm）会对列表进行**快照**，因此在一段运动执行期间可以上传并校验新的列表。运动完成后该轴自动解除使能，故每次运行都需要重新执行 `PVAJArm = 1`。

每经过 `Gap` 个控制周期消耗一行；根据 `Mode` 表头项，各行既可解释为绝对位置，也可解释为相对于 `Begin` 时刻轴所在位置的相对量。

## 关键字一览

| 关键字 | 作用 |
|---|---|
| [PVAJList](PVAJList.md) | 轨迹表：表头加最多 8192 行 P/V/A/J |
| [PVAJValidate](PVAJValidate.md) | 在允许使能前校验列表 |
| [PVAJArm](PVAJArm.md) | 快照已校验的列表，使该轴可被 `Begin` 启动 |
| [PVAJStatus](PVAJStatus.md) | 状态、当前行与剩余行数 |
| [PVAJPosTol](PVAJPosTol.md) | 校验器使用的位置连续性容差 |
| [PVAJVelTol](PVAJVelTol.md) | 校验器使用的速度连续性容差 |

## 组行为（模式 23）

一次 `Begin` 启动所有成员，且**除非所有成员均已就绪，否则该命令被拒绝**——部分启动的组将不再遵循协调路径。拒绝错误码为 `400`（被命令的轴自身未使能）、`402`（某成员未使能）和 `401`（某成员未处于电机使能状态，或已在运动中）。

各成员的列表长度不必相同。先到达自身列表末尾的成员将保持其最终位置，并持续报告"运动中"，直到最后一个成员完成，因此从外部看该组作为单一运动开始并结束。

当该组停止时，未收到命令的成员通过 [MotionReason](../05-motion-status/MotionReason.md) 报告原因：

| MotionReason | 含义 |
|---|---|
| `42` | 另一成员被停止 |
| `43` | 另一成员被中止 |
| `44` | 另一成员触发限位开关 |
| `45` | 另一成员进入电机关闭状态 |

## 产品适用性

PVAJ **仅适用于 central-i v5（AGM800）**。每轴列表为 32771 个 double —— 约 3 MB，使能快照再占用同等空间 —— 这对 AGM800 的 DDR 而言不足为奇，但即便只有一个轴也已超出 C2000 产品的整个外部 RAM 池。

在不具备该功能的产品上，这六个助记符是**缺失而非以桩形式存在**，这是有意为之：上位机通过查询 `PVAJList` 是否存在来检测 PVAJ 支持，而在无法提供该功能的控制器上，该探测必须失败。
